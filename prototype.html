Testing guide

📌 Scenario 1: Shared System Initiation & Governance Interception

User Input: Writes prompt: "Mark all the projects completed".

Agent Logic: Runs a 4-second workspace database audit instead of blindly marking projects completed.

System Output: Generates Project Closeout Audit card:
Status: PRJ-005 • Bowen-Chapman - Enterprise Rollout flagged as Blocked.
Blocker Reason: 1 open milestone task preventing closeout.
Action Paths: Presents dual options (Auto-resolve blockers & complete vs. Inspect PRJ-005 details).

Branch A: Manual Inspection & Nested Triage Flow

  • Step 1 — Deep Inspection:
    Action: User clicks Inspect PRJ-005 details.
    Agent Logic: Executes a 10-second dependency lookup down to root cause level.
  • Step 2 — 4-Level Conflict Matrix Rendering:
    Agent Output: Renders the Conflict Matrix (Triage Flow) table:
    L1 Project: PRJ-005 (Blocked)
    L2 Milestone: MST-001 (Blocked)
    L3 Subtask: TSK-0003 (Blocked)
    L4 Root Cause: TSK-0004 • Starter Kit Walkthrough (Violation: 0.00h logged) with explicit input/resolve action controls (02:30 | Resolved).
  • Step 3 — Explicit Manual Action:
    Action: User triggers command: "Resolve TSK-0004 + Starter Kit Walkthrough by logging the time as 02:30".
  • Step 4 — Final Closeout State:
    Agent Logic: Updates time log for TSK-0004 (8 seconds), clears dependency blockers across all 4 levels, and marks all active projects as completed.
    Agent Output: Displays all-green Conflict Matrix (Triage flow) state (Resolved: Time logged) followed by an inline micro-survey (Was this resolution accurate?).

Branch B: One-Click Autonomous Auto-Resolve Flow

  • Step 1 — Direct Auto-Resolve Trigger:
    Action: User clicks Auto-resolve blockers & complete directly on the audit card.
  • Step 2 — Autonomous Time Calculation:
    Agent Logic: Processes for 10 seconds, calculates expected missing time based on historical logging averages (deriving 02:30 hours), logs time on behalf of the user, and closes all projects.
  • Step 3 — Instant Resolution & Feedback:
    Agent Output: Renders the identical all-green Conflict Matrix (Triage flow) showing all 4 dependency levels resolved, accompanied by the completion message and feedback micro-survey.

📌 Scenario 2: Rebalancing Workload ("Wrap Lisa's work within this week")

This flow demonstrates how the agent handles team workload audits and offers both an automated fast-path and full manual control.

  • Step 1: Enter or click the sample prompt: "Wrap Lisa's work within this week".
  • Step 2: Review the Lisa's Workload Audit card that appears after the 4-second audit.
  • Step 3: Test one of two available decision branches:
    • Option A (1-Click Autonomous Path): Click Auto-assign to team.
      What to watch for: The agent automatically calculates sprint capacity, logs pending hours, reassigns tasks to low-bandwidth team members, and renders a clean Task Reassignment Matrix.
    • Option B (Granular Inspection Path): Click Inspect & adjust Lisa's tasks.
      What to watch for: The agent renders interactive forms with hour inputs and team capacity dropdowns. Type: log 2.5h to TSK-0217, assign TSK-0218 to Cameron Fisher other TSK-0219 to April Frost to see explicit manual overrides resolve into the matrix.
  • Step 4 (Fallback Handling): Type "Notify Lisa via Slack" to see how the system gracefully handles missing third-party integrations with explicit non-blocking warning states.
